# Test cases

QA and UAT assets, kept in the repository so they are reviewed with the change they cover.

| Folder | For |
|---|---|
| [`functional/`](functional/) | manual functional cases, one folder per feature |
| [`integration/`](integration/) | cross-component and integration-system cases |
| [`api/`](api/) | API cases |
| [`ui/`](ui/) | screen and usability cases |
| [`regression/`](regression/) | the regression pack |
| [`security/`](security/) | security cases |
| [`UAT/`](UAT/) | user acceptance |

**Automated tests** are not duplicated here. They live next to the code (`backend/**/src/test`, `frontend/src/**/*.test.*`) and are named `VYBnnnn_ACn_shortDescription`, so each traces to a requirement; [`automated-tests-index.md`](automated-tests-index.md) lists them by requirement (generated by `scripts/generate-requirements-docs.py`).

**Manual cases** are one Markdown file per case, `TC-<FEATURE>-<nnn>.md`, in the feature's folder (for example `functional/portfolio/TC-PF-001.md`), from [`TEMPLATE.md`](TEMPLATE.md). Every functional feature should have cases, and every major feature acceptance criteria. No manual cases have been authored yet; the automated suite is what exists.
